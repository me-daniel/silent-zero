# Audit results

Generated by `python -I audit/classify.py --raw <outputs> --out <dir> <builds>`. The class definitions are in the docstring of `audit/classify.py`. One greedy run per build. On this stack, greedy runs reproduce byte-identically across server restarts; this was checked for Q8_0 and IQ3_XXS on multi_turn_base.

## Setup

- **Model:** Qwen3-4B-Instruct-2507, GGUF, served with llama.cpp `llama-server` b10964 on Apple Silicon (Metal).
  - Settings: one slot (`-np 1`), greedy (temperature 0, top-k 1), server prompt cache off (`--cache-ram 0`).
- **Benchmark:** BFCL at commit `6ea5797`, model entry `Qwen/Qwen3-4B-Instruct-2507-FC` (handler `QwenFCHandler`).
- **Categories:**
  - `simple_python`: 400 items;
  - `live_simple`: 258 items;
  - `multi_turn_base`: 200 tasks, counted per assistant step.

## Single-turn with the patched evaluator in tolerant mode

`patch/verify.py --mode tolerant` re-scores the same saved outputs, accepting a final unclosed `<tool_call>` and loose whitespace. No new model outputs are involved. Adding `SILENT_ZERO_REPAIR_KEYS` gives the same numbers: dropped keys only occur in multi-turn.

|---|---|---|---|---|

| IQ3_XXS | 65.75 | 91.00 | 59.69 | 79.07 |
| IQ3_XXS_R | 60.50 | 91.25 | 56.98 | 79.46 |

| IQ3_XXS_T | 87.00 | 89.50 | 72.09 | 74.42 |

| IQ3_XXS_W | 91.25 | 91.25 | 75.58 | 75.58 |
| IQ3_XXS_V | 91.25 | 91.25 | 75.58 | 75.58 |

On `simple_python`, the tolerant scores of all IQ3_XXS builds lie within 89.50–91.50, including the two builds with the public imatrix (official 65.75 and 60.50). So on this category, the official gap between these builds comes almost entirely from the missing closing tag. On `live_simple`, the tolerant scores spread more (74.42–79.46), and the two public-imatrix builds end up highest. All numbers are from one greedy run per build.
